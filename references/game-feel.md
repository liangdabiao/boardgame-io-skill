# Game Feel Reference: 音效、动效与行动演出

让 boardgame.io 游戏从"能玩"变成"好玩"的表现层模式。全部来自实战
项目验证（西游斗法：AI 对手、隐藏手牌、apiz 生成卡图与 BGM）。

## 状态差分 FX 引擎（核心模式）

在 board 组件里用 `useRef` 保存上一帧状态快照，`useEffect([G, ctx])`
里做值级差分，一次对比同时驱动四路输出：**动效类名、音效、战报日志、
中央演出**。关键优点：AI/bot 的行动走同一条状态更新路径，全部演出
自动覆盖双方，无需在 AI 代码里插任何演出钩子。

检测项清单（值比较，天然幂等——同一状态多次通知不会重复触发）：

| 差分 | 事件 |
|---|---|
| 场槽 null→card / card→null | 召唤 / 入墓（同侧同帧合并 = 祭品召唤） |
| `attacked` false→true | 攻击（记录攻击方 → 突进方向、胜负归因；攻击者死亡时用 log prop 兜底，见下） |
| LP 下降 | 伤害（飘字 + 震屏 + 与攻击差分合并出"击破/反制/同归于尽/直取"叙事） |
| 手牌长度 -1 且无上场 | 法术（按效果分类，见下） |
| 手牌长度增加 | 抽牌 / 回合开始摸牌 |
| `ctx.gameover` 出现 | 终局演出 |

## 行动演出（隐藏信息游戏的必需品）

**问题**：`playerView` 隐藏对手手牌后，对手的行动对玩家不可见——
"对方出了什么牌、打了谁、结果如何"必须有叙事层，否则不可玩。

**最终定版的事件通知架构**（经用户逐项确认，多轮反馈收敛）：

| 事件 | 界面表现 |
|---|---|
| 怪兽 vs 怪兽攻击 | 双卡对决弹窗 + 后果标在卡上（"毁"徽章 + 红色伤害数字），一帧看完整场战斗 |
| 对手召唤 / 影响场面的法术 | 卡图弹窗（大卡 + 标题） |
| 其余重要事件（直接攻击、抽卡法术、回复等） | **文字弹框**（金边黑底文字条，~1.4s） |
| 卡被破坏 | 原位消散残影动画 |
| 伤害 | 法力条飘字 + 震屏 + 音效 |

铁律：**任何一方的任何重要动作都必须有屏幕告知——玩家不看战报
日志**，日志只是辅助记录。AI 行动节奏与演出时长匹配（~1.1s/步）。

演出实现要点（全部实战踩坑换来的最终结论）：

1. **绝不排队逐个弹出**——最新事件直接替换当前画面，任何时刻最多
   一个弹窗；AI 一回合 3-4 个动作排队展示必被报告"重复 3 次"。
2. **AI 的召唤/法术必须弹窗展示**（玩家不看战报日志！），玩家自己
   的出牌零弹出；攻击对决演出双方都放。
3. **居中定位**：弹窗锚定玩家注视的游戏区域（棋盘），不要锚定
   浏览器视口——面板/窗口尺寸不等于棋盘位置。做法：棋盘容器
   `position: relative; overflow: hidden`，弹窗 `position: absolute`
   四边撑满棋盘 + 内部 flex 居中（已实测偏差 dx=0 dy=0）。
   **头号天坑——动态类名碰撞**：`stage-${kind}` 生成的 `stage-card`
   与弹窗内部组件类 `.stage-card` 同名，容器被组件规则命中
   （position:relative + 固定宽度 + 动画 transform），任何居中方案
   都"无效"，症状是弹窗缩在左上角。动态拼接的类名必须检查与既有
   类的碰撞；排查这类问题的正确手段是取证元素的计算样式
   （getComputedStyle + 命中规则 + 父级链），而不是反复换定位方案。
4. React key 必须稳定（`Math.random()` 作 key 每帧重挂载元素）。
5. **禁止延迟弹窗序列**（如对决画面 1.2s 后再弹伤害数字）：AI 按固定
   间隔连续行动，延迟弹出的旧信息会覆盖正在显示的新画面——时序彻底
   混乱。每个事件一帧演完（伤害/结果直接融合进对决画面）。
6. **攻击者死亡的战斗是检测盲区**：同归于尽/被反制时 `attacked` 标记
   随卡片一起消失，标记差分检测不到攻击发生（弹窗+战报整条静默
   丢失）。兜底：用 boardgame.io 的 `log` prop——最后一次 move 是
   `attack` 且有场上卡消失时，按该 move 的 playerID/args 归因攻击方。
7. **页面加版本角标**（如"v3"小字）：Vite HMR 对模块级
   `Client({ board })` 的组件树更新不可靠，用户浏览器可能长期跑
   旧代码——你改的代码"看起来没生效"时，先让用户强刷并用角标确认
   版本，再排查代码。调试自身：dev server 重启可强制全网刷新。

**对手法术识别**（手牌不可见时按差分效果分类，用于战报叙事）：
LP 上升→治疗卡；无攻击标记的对方场上破坏→点杀卡；墓地减少+同侧
上场→复活卡；手牌净增 1（抽2打1）→抽卡法术；兜底"发动了法术"。

## Web Audio 合成音效（零资源、零版权）

`src/sfx.js` 模式（浏览器专用文件，测试不加载可用子路径导入）：

- **懒初始化 AudioContext + 首次交互 resume**（浏览器自动播放策略；
  在 board 根元素 `onClickCapture` 里调 `ensureUnlocked()`）
- 两个构件就够全部音效：`tone({freq, type, dur, vol, at, slide})`
  （振荡器+包络）与 `noise({dur, vol, lowpass, hp})`（衰减噪声）
- 每个事件音效用 guard 包装（开关关闭/异常时静默），开关存 localStorage
- 事件音效表：召唤（低频锣+泛音）、攻击（带通噪声+下滑音）、受击
  （低通钝响）、法术（上行琶音）、抽牌（高通短噪）、消散（下行三连）、
  回合（钟磬）、胜利/落败（上/下行四音）

## BGM 生成（配合 apiz 等 AI 网关）

- `minimax/music-gen` **必填 `lyrics` 参数**，器乐曲传
  `--params '{"lyrics":"[inst]"}'`（缺了报 HTTP 400）
- `--wait` 结束时 CLI 输出可能**缺 result 载荷**（只有 task_id）→
  用 `apiz tasks get <id>` 拿 `result.audio_url`，curl 下载
- 播放：`<audio loop>` + 首次 pointerdown 后 `play()` + 音量 ≤ 0.4
  不抢音效；开关独立于音效开关，偏好存 localStorage

## CSS 动效集（直接可抄）

- **破坏/消散必须用"残影卡"**：卡被移出状态的同一帧，槽位就渲染为
  空占位——动画类若挂在槽位上等于播给空气（玩家看到"毫无效果"，
  实战中被当成 bug 报告）。正确做法：diff 检测到消失时，在该槽位
  渲染一张被毁卡的残影（完整卡面 + fx-destroy 类），650ms 后移除。
- 召唤弹入：`cubic-bezier(0.34, 1.56, 0.64, 1)` 弹性放大 + 亮度闪
  （召唤能自然工作是因为新卡本来就在场上）
- 攻击突进：translateY ±46px（我方向上/敌方向下，按攻击方）+ brightness
- 伤害飘字：法力条内绝对定位，上浮淡出 `forwards`
- 震屏：大额伤害（≥1000）时容器 0.3s 微位移
- 终局：胜利弹性放大/落败沉重缩入
- 可用手牌光晕呼吸；**禁 hover transform**（指针下"躲牌"）

## 浏览器测试经验（血泪教训）

- **单元测试通过 ≠ 浏览器可玩**：game.js 的 move 在 Node 测试中全部
  通过，但浏览器中的 Local multiplayer 传输层可能静默丢弃 move。
  唯一可靠的验证方式是在真实浏览器中走完完整游戏流程
- **浏览器自动化工具不可靠**：CUA click 和 Playwright locator click
  经常因 "broker response id mismatch" 失败。如果自动化点击失败，
  不要认为游戏代码有 bug——先让用户手动点击验证
- **去掉 multiplayer: Local() 会让 AI 对手消失**：这是"能点击按钮"
  的错误修复方式。正确做法是保留 Local() 并修复真正的 bug
- **CSS 缺失会导致按钮不可见/不可点**：如果 board.jsx 用了自定义
  class（如 .episode），必须在 CSS 中定义样式，否则按钮渲染异常
- **交付前必须自己玩几个完整回合**：不是点一下就完——要走完
  剧情 → 召唤 → AI 行动 → 攻击 → 分出胜负的完整循环

## 调试与协作经验

- **"CSS 看着对但渲染不对"→ 先怀疑页面在跑旧代码**。Vite HMR 对
  模块级 `Client({ board })` 闭包可能不生效（入口组件持有旧引用）；
  让用户强制刷新（Ctrl+F5）/无痕窗口验证后再查代码
- 自动化测试点击通道不稳时，改走 **CUA 坐标点击**：
  `dom_cua.get_visible_dom()` 拿元素 rect → `cua.click({x, y})`
  （与 Playwright locator 点击是不同管线）
- **UI 投诉先复述理解、列改法、用户确认后再动代码**——直接改极易
  越改越错（本参考的多条铁律都来自确认前的错误方向）。不确定时用
  2-3 个具体选项向用户提问（如"文字弹框和卡图弹窗如何分工？"），
  一次锁定规格，远好于猜错后返工
- **听懂"不要 X"的确切含义**：用户说"直接攻击不需要弹框"，真实
  意思往往是"不需要这种卡图弹窗"，但事件本身仍需文字告知——
  否定的是形式还是告知本身，必须澄清
