# Game Feel Reference: 音效、动效与行动演出

让 boardgame.io 游戏从"能玩"变成"好玩"的表现层模式。全部来自实战
项目验证（西游斗法：AI 对手、隐藏手牌、apiz 生成卡图与 BGM）。

## 状态差分 FX 引擎（核心模式）

在 board 组件里用 `useRef` 保存上一帧状态快照，`useEffect([G, ctx])`
里做值级差分，一次对比同时驱动四路输出：**动效类名、音效、战报日志、
中央演出**。关键优点：AI/bot 的行动走同一条状态更新路径，全部演出
自动覆盖双方，无需在 AI 代码里插任何演出钩子。

检测项清单（值比较，天然幂等——同一状态多次通知不会重复触发）：

| 差分 | 事件 |
|---|---|
| 场槽 null→card / card→null | 召唤 / 入墓（同侧同帧合并 = 祭品召唤） |
| `attacked` false→true | 攻击（记录攻击方 → 突进方向、胜负归因） |
| LP 下降 | 伤害（飘字 + 震屏 + 与攻击差分合并出"击破/反制/同归于尽/直取"叙事） |
| 手牌长度 -1 且无上场 | 法术（按效果分类，见下） |
| 手牌长度增加 | 抽牌 / 回合开始摸牌 |
| `ctx.gameover` 出现 | 终局演出 |

## 行动演出（隐藏信息游戏的必需品）

**问题**：`playerView` 隐藏对手手牌后，对手的行动对玩家不可见——
"对方出了什么牌、打了谁、结果如何"必须有叙事层，否则不可玩。

**实战定论**（来自真实项目的三轮用户反馈）：
- **保留**：攻击对决演出（双方）——攻击方 ⚔ 防守方卡面对峙 + 大伤害
  数字，`fixed + 50% + translate(-50%,-50%)` 居中，最新事件直接替换
  当前画面（不排队）。用户明确要求保留。
- **移除**：召唤/法术的出牌弹窗——用户两次报错后要求整体去掉；
  由战报日志 + 道场动效 + 音效替代，零投诉。
- 可靠组合 = 战报日志（完整叙事）+ 场面动效（道场可见变化）+ 音效 +
  仅攻击的对决演出。

若做攻击对决演出，注意：

1. **绝不排队逐个弹出**——最新事件直接替换当前画面，任何时刻最多
   一个弹窗；AI 一回合 3-4 个动作排队展示必被报告"重复 3 次"。
2. **出牌弹窗（召唤/法术）不要做**，攻击对决演出双方都放；
   玩家自己的出牌零弹出。
3. 居中定位用 `position: fixed; left: 50%; top: 50%;
   transform: translate(-50%, -50%)`（absolute + inset 依赖定位父级
   的方案在实战中诡异失效且查无原因）。
4. React key 必须稳定（`Math.random()` 作 key 每帧重挂载元素）。

**对手法术识别**（手牌不可见时按差分效果分类，用于战报叙事）：
LP 上升→治疗卡；无攻击标记的对方场上破坏→点杀卡；墓地减少+同侧
上场→复活卡；手牌净增 1（抽2打1）→抽卡法术；兜底"发动了法术"。

## Web Audio 合成音效（零资源、零版权）

`src/sfx.js` 模式（浏览器专用文件，测试不加载可用子路径导入）：

- **懒初始化 AudioContext + 首次交互 resume**（浏览器自动播放策略；
  在 board 根元素 `onClickCapture` 里调 `ensureUnlocked()`）
- 两个构件就够全部音效：`tone({freq, type, dur, vol, at, slide})`
  （振荡器+包络）与 `noise({dur, vol, lowpass, hp})`（衰减噪声）
- 每个事件音效用 guard 包装（开关关闭/异常时静默），开关存 localStorage
- 事件音效表：召唤（低频锣+泛音）、攻击（带通噪声+下滑音）、受击
  （低通钝响）、法术（上行琶音）、抽牌（高通短噪）、消散（下行三连）、
  回合（钟磬）、胜利/落败（上/下行四音）

## BGM 生成（配合 apiz 等 AI 网关）

- `minimax/music-gen` **必填 `lyrics` 参数**，器乐曲传
  `--params '{"lyrics":"[inst]"}'`（缺了报 HTTP 400）
- `--wait` 结束时 CLI 输出可能**缺 result 载荷**（只有 task_id）→
  用 `apiz tasks get <id>` 拿 `result.audio_url`，curl 下载
- 播放：`<audio loop>` + 首次 pointerdown 后 `play()` + 音量 ≤ 0.4
  不抢音效；开关独立于音效开关，偏好存 localStorage

## CSS 动效集（直接可抄）

- 召唤弹入：`cubic-bezier(0.34, 1.56, 0.64, 1)` 弹性放大 + 亮度闪
- 攻击突进：translateY ±46px（我方向上/敌方向下，按攻击方）+ brightness
- 伤害飘字：法力条内绝对定位，上浮淡出 `forwards`
- 震屏：大额伤害（≥1000）时容器 0.3s 微位移
- 入墓消散：缩小旋转淡出；终局：胜利弹性放大/落败沉重缩入
- 可用手牌光晕呼吸；**禁 hover transform**（指针下"躲牌"）

## 调试与协作经验

- **"CSS 看着对但渲染不对"→ 先怀疑页面在跑旧代码**。Vite HMR 对
  模块级 `Client({ board })` 闭包可能不生效（入口组件持有旧引用）；
  让用户强制刷新（Ctrl+F5）/无痕窗口验证后再查代码
- 自动化测试点击通道不稳时，改走 **CUA 坐标点击**：
  `dom_cua.get_visible_dom()` 拿元素 rect → `cua.click({x, y})`
  （与 Playwright locator 点击是不同管线）
- **UI 投诉先复述理解、列改法、用户确认后再动代码**——直接改极易
  越改越错（本参考的多条铁律都来自确认前的错误方向）
